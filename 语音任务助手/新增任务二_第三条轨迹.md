# 新增任务二：第 3 套轨迹

新版 `voice_tasks.py` 保留原任务一，并增加任务二，每个口令仅启动一遍完整流程，不循环也不排队。

| 口令 | 数据目录 | 配套起点 |
| --- | --- | --- |
| 执行任务一 / 完成任务一 | `~/lerobot/recordings/so101_pick_place_02` | `~/lerobot/poses/pick_place_02_start.json` |
| 执行任务二 / 完成任务二 | `~/lerobot/recordings/so101_pick_place_20261015_183432` | `~/lerobot/poses/so101_pick_place_20261015_183432_start.json` |

上表名称来自用户本次提供的 Ubuntu 真实路径。当前 `voice_tasks.py` 的默认值仍为保守占位路径，避免在未核验 Ubuntu 文件时误启动；运行任务二必须显式传入这两个参数。程序会检查起点文件绑定的真实轨迹目录，混用时拒绝启动，不会回退成任务一。

## 复制新版（保留旧文件）

先等任务结束，Ctrl+C 退出旧语音助手。
打开 Windows/Codex 本目录的 `voice_tasks.py`，复制完整代码。
Ubuntu 执行：

```bash
conda activate so101_voice
nano ~/so101_voice/voice_tasks_v2.py
```

将完整代码粘贴进新文件，Ctrl+O、回车保存，Ctrl+X 退出。若新文件已存在，应替换整个文件正文，不能追加。

## 先检查配置

```bash
python ~/so101_voice/voice_tasks_v2.py --port /dev/ttyACM0 --check-config
```

应同时显示任务一绑定第 2 条、任务二绑定第 3 条，并显示检查通过。
此步骤不打开串口。数据路径、配套起点或任务执行器不存在时，先处理错误，不要开始任务二。

自定义任务二路径的示例（将中文占位内容替换为实际路径）：

```bash
python ~/so101_voice/voice_tasks_v2.py --port /dev/ttyACM0 \
  --dataset2 '实际第三条数据目录' \
  --pose2 '实际第三条配套起点JSON路径' \
  --check-config
```

## 实际运行

前提：第三条已通过原 `so101_home.py demo --pose ... --execute` 完整流程验证。归位是关节插值，不具备自动避障。

```bash
python ~/so101_voice/voice_tasks_v2.py --port /dev/ttyACM0 --execute
```

自定义路径时，运行、检查和安装快捷方式均需带上相同的 `--dataset2`、`--pose2` 参数。
恢复对应场景、确认夹爪空载和整条路径无遮挡后，说“执行任务二”。
程序调用原任务执行器，并显式传入第三条专属起点；轨迹从该起点文件中的绑定读取。程序不修改原执行器的回放限幅，继续沿用用户已改成 5 的配置。

任务一或任务二运行期间，任何其他启动口令都会被忽略。正常完成后 3 秒恢复待命。停止或异常退出后锁定启动，检查现场并退出重开后恢复。

“停止任务”为辅助软件中断，不代替硬件急停。异常运动应立即切断 F 电机电源。

## 更新桌面图标

新版首次联动验证成功后，Ctrl+C 退出，再执行：

```bash
python ~/so101_voice/voice_tasks_v2.py --port /dev/ttyACM0 --install-shortcut
```

程序会备份现有同名桌面图标，再更新为运行新版。不要同时开启旧版和新版，二者共用单实例锁。
如端口在重启或重新插拔后改变，先重新识别从臂，并同步修改命令中的 `--port`。
