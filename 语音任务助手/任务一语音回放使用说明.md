# 任务一：语音触发第 2 套轨迹

## 已确定的配置

- 语音口令：“执行任务一”或“完成任务一”。
- 对应数据：`~/lerobot/recordings/so101_pick_place_02`。
- 对应起点：`~/lerobot/poses/pick_place_02_start.json`。
- 任务执行器：Ubuntu 内已有的 `~/lerobot/so101_home.py`。
- 使用原执行器的 `demo --port /dev/ttyACM0 --pose ... --execute` 接口；不修改它的限幅、校准、归位逻辑或数据。
- 语音环境：`so101_voice`；机械臂环境：`so101`。
- 用户已反馈完整流程跑通；本次截图确认实时口令识别成功，并确认两套轨迹及起点文件在 Ubuntu 中存在。新增语音与机械臂联动尚待用户实测。

如果期间重启或重新插拔 USB，先重新核对 F 从臂端口。任务执行器仍会按照起点配置核对控制板身份及校准。运行期间不要再开启遥操作、其他回放或归位进程。

## 1. 复制程序到 Ubuntu（一次）

在 Codex 文件编辑器打开同目录 `voice_tasks.py`，复制完整正文。
在 Ubuntu 终端执行：

```bash
conda activate so101_voice
nano ~/so101_voice/voice_tasks.py
```

在 nano 内按 Ctrl+Shift+V 粘贴，Ctrl+O、回车保存，Ctrl+X 退出。
若目标文件已有内容，先核对，不要把新代码追加到旧代码后。

## 2. 只读配置检查

```bash
python ~/so101_voice/voice_tasks.py --port /dev/ttyACM0 --check-config
```

应明确显示第 2 套数据目录与 `pick_place_02_start.json`，并显示配置检查通过。
此检查不打开串口，不证明现场路径无遮挡；实际 USB 身份、校准、反馈和运动检查继续由原任务执行器完成。

默认机械臂解释器按语音环境的相邻 `so101` 环境定位。如找不到，可在原环境运行 `conda run -n so101 python -c "import sys; print(sys.executable)"`，再用 `--robot-python` 指定该绝对路径。

## 3. 首次语音联动

准备好已经验证过的场地：底座固定，夹爪空载，归位和回放路径无遮挡，物体按录制第 2 套时的位置摆放。首次联动建议空载验证，结束后再带物体演示。

```bash
python ~/so101_voice/voice_tasks.py --port /dev/ttyACM0 --execute
```

启动只进入待命。说“执行任务一”，停顿后开始归位→第 2 套轨迹回放→归位。正常结束后恢复待命，不自动循环、不排队；再次下达命令前需重新摆放物体。

- “查询状态”：显示待命、执行中、停止中或锁定。
- “停止任务”：向任务进程组（含官方回放子进程）发送 SIGINT，并锁定启动。
- Ctrl+C：退出监听；有任务时请求中断并等待退出。
- 异常退出或停止后必须检查现场，再退出重开语音助手，才能再次启动。
- 语音识别可能误识别或延迟；语音停止和 Ctrl+C 都不代替硬件急停。异常运动应立即切断 F 电机电源。
- 结束后电机可能仍保持上力，按原归位工具说明支撑并卸力，禁止徒手强扳。

程序用单实例锁阻止同时打开两个相同助手；它不能阻止用户手动运行其他机械臂程序。完整句子完全匹配后才接受命令，不将识别文本当作 shell 命令。

## 4. 创建桌面图标（语音联动验证成功后）

先 Ctrl+C 退出助手，再执行：

```bash
python ~/so101_voice/voice_tasks.py --port /dev/ttyACM0 --install-shortcut
```

桌面出现“SO101 语音任务助手”。如提示不可信，右键选择“允许启动”。
之后双击会打开状态终端并进入实际执行模式的待命状态，说“执行任务一”才启动运动。
端口、模型、起点和数据配置会写入快捷方式。如果端口变化，重新核对后调整启动命令；不同内容的旧快捷方式不会自动覆盖。
