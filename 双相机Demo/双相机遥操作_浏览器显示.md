# 双相机遥操作：浏览器显示，避开 Rerun 显卡限制

2026-10-21 日志确认：L=`/dev/ttyACM1`、F=`/dev/ttyACM0` 均连接；腕部 `/dev/video0`、旁侧 `/dev/video2` 均由 LeRobot 连接成功，并进入约 15 Hz 的遥操作循环。Rerun 窗口报 GPU 不支持 `R32Float`，随后显示数据队列出现阻塞提示。这与此前 OpenCV HighGUI 不可用是两个不同的显示问题。

这里用 `teleop_web.py` 转发原遥操作参数，强制 `display_data=false`；原本读取的双相机 RGB 图像转换为 JPEG，通过 Ubuntu 回环地址提供浏览器显示。网页不另外打开相机，不改变 PID、限幅或电机编号。

**这是会驱动机械臂的遥操作程序，不是纯相机预览。** 先固定底座、清空夹爪、让两臂姿态接近，给腕部相机线留足活动余量。

## 1. 退出旧程序

扶稳前臂后，按 `Ctrl+C` 停止旧的 `lerobot-teleoperate`，等待两臂断开、终端重新显示命令提示符。

同时退出 `preview_web.py`，否则它会占用两台相机和 8765 端口。本流程只运行新的 `teleop_web.py`。

如果旧控制程序仍未退出，不要再开一个控制程序；先确认进程退出。异常运动时立即切断 F 电机电源，`Ctrl+C` 不是硬件急停。

## 2. 复制新文件到 Ubuntu

Windows 文件：`D:\具身智能\双相机Demo\teleop_web.py`。

在 Windows/Codex 打开它，全选复制文件正文。Ubuntu 终端运行：

```bash
nano ~/lerobot/teleop_web.py
```

`Ctrl+Shift+V` 粘贴；`Ctrl+O`、回车保存，`Ctrl+X` 退出。

```bash
conda activate so101
cd ~/lerobot
python teleop_web.py --help
```

## 3. 启动双相机遥操作

以下端口沿用这次日志已证实的连接。如果重新插拔或重启，先重新核对机械臂端口和相机身份。

```bash
python teleop_web.py \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=follower_arm \
  --robot.max_relative_target=5 \
  --robot.cameras='{"wrist":{"type":"opencv","index_or_path":"/dev/video0","width":640,"height":480,"fps":15,"fourcc":"MJPG"},"side":{"type":"opencv","index_or_path":"/dev/video2","width":640,"height":480,"fps":15,"fourcc":"MJPG"}}' \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM1 \
  --teleop.id=leader_arm \
  --fps=15 \
  --display_data=false
```

根据已有流程，确认连接角色、最终正确的校准文件后再选择复用。连接后可能开始跟随，提前准备好姿态。

## 4. 看图并做小范围测试

在 **Ubuntu 的 Firefox** 地址栏打开：

```text
http://127.0.0.1:8765
```

应看到腕部、旁侧两路画面。刚启动但相机尚未连接时，页面暂时提示等待是正常的。图像更新来自 LeRobot 自己读取的 `wrist`、`side` 观测；没有新图像超过两秒时不再发送旧帧。

浏览器 JPEG 刷新做了节流，并非精确的相机帧率测量。先缓慢移动 L，确认 F 正常跟随、两路图像持续更新、相机线没有牵拉。程序只遥操作，不保存视频或数据集。

## 5. 结束

扶稳从臂，在控制终端按 `Ctrl+C`。原 LeRobot 流程会断开机械臂和相机，默认退出时卸力；网页服务随后关闭。等待终端重新显示提示符，再进行下一步录制。

若网页端口冲突，确保原预览已退出。也可给新程序添加 `--web-port=8766`，并在 Ubuntu 浏览器访问 `http://127.0.0.1:8766`。
