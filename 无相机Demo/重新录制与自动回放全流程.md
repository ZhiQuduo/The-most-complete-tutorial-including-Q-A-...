# 第 2 条无相机轨迹：重新录制、保存起点、回放和自动归位

日期：2026-10-15。适用于已经在 Ubuntu 完成 `so101_home.py` 起点保存、只读检查和空载归位验证的当前设备。

全部命令在 **Ubuntu 虚拟机终端**执行。每一步成功结束后再执行下一步，不要把所有步骤一次性粘贴运行。

本次新数据使用 `so101_pick_place_02`，新起点使用 `pick_place_02_start.json`，保留原来的第 1 条轨迹及起点。

## 1. 进入环境，核对端口

```bash
conda activate so101
cd ~/lerobot
```

终端前缀应为 `(so101)`。本次会话已经确认 F=`/dev/ttyACM0`、L=`/dev/ttyACM1`。如果期间重启或重新插拔过 USB，先按重启说明重新识别两块板，并替换下面的端口。

需要恢复权限时执行：

```bash
sudo chmod 666 /dev/ttyACM0 /dev/ttyACM1
```

不要同时运行其他遥操作、回放或归位程序。

## 2. 准备新录制的初始姿态

如果从臂已经在刚才验证成功的起点保持上力，可以直接沿用。若已偏离，先拿走物块、确认返回路径无遮挡，再回到旧起点作为这次录制的准备姿态：

```bash
python so101_home.py home --port /dev/ttyACM0 --execute
```

这是在录制前使用旧起点，后续会为第 2 条轨迹单独保存新起点。

固定底座，在 A 放好物块，B 保持空。轻缓调整 L 主臂，使它与 F 从臂的关节姿态、夹爪状态尽量一致，减少连接后追赶目标的动作。F 已保持上力时不要徒手掰它。也不要强扳不能轻缓活动的 L 关节。

## 3. 录制第 2 条轨迹

如果之前没有使用过 `so101_pick_place_02`，执行：

```bash
lerobot-record \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=follower_arm \
  --robot.max_relative_target=5 \
  --robot.disable_torque_on_disconnect=false \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM1 \
  --teleop.id=leader_arm \
  --dataset.repo_id=local/so101_pick_place_02 \
  --dataset.root="$HOME/lerobot/recordings/so101_pick_place_02" \
  --dataset.single_task="Move the foam block from A to B" \
  --dataset.fps=30 \
  --dataset.num_episodes=1 \
  --dataset.episode_time_s=60 \
  --dataset.reset_time_s=0 \
  --dataset.video=false \
  --dataset.push_to_hub=false \
  --dataset.no_stamp=true \
  --display_data=false \
  --play_sounds=false
```

如果提示使用已有校准文件，确认连接的是正确的臂、文件是最终正确校准，再按回车。看到 `Recording episode 0` 后：

1. 前 3～5 秒保持主臂稳定。
2. 操纵 L 完成一次靠近 A、张开、夹取、抬起、搬到 B、放下和退开。
3. 结束动作后让夹爪停在空旷位置，保持稳定，等待录制满 60 秒。
4. 等待保存并正常退出，不要用 `Ctrl+C` 作为正常保存方式。异常运动时仍应立即停止。

这次设置 `disable_torque_on_disconnect=false`，录制结束后从臂保持上力，不会主动卸力。不要强扳关节；后续结束使用时按第 8 步卸力。

若提示目标数据目录已存在，先停止，保留旧数据。想再新录一条时将本文的数据集名称、目录和起点文件统一改为 `03` 等新编号，不要直接删除旧轨迹，也不要随意添加 `--resume=true`。

## 4. 为新轨迹保存专属起点

原来的归位文件绑定第 1 条轨迹，所以第 2 条必须另存：

```bash
python so101_home.py save-start \
  --port /dev/ttyACM0 \
  --dataset "$HOME/lerobot/recordings/so101_pick_place_02" \
  --repo-id local/so101_pick_place_02 \
  --pose "$HOME/lerobot/poses/pick_place_02_start.json"
```

它从新轨迹第一帧提取从臂实际位置，不要求你现在手动把 F 摆回起点。操作只读电机，不驱动。成功应显示“起点已保存”。

`save-start` 输出的第一张表是起点与自身比较，差值为零不代表机械臂当前已在起点；下一条 `check` 才检查真实当前位置。

```bash
python so101_home.py check \
  --port /dev/ttyACM0 \
  --pose "$HOME/lerobot/poses/pick_place_02_start.json"
```

出现错误就停在这一步，先处理错误。原录制和原校准都不需要因检查失败而删除。

## 5. 空载返回新起点

拿走物块、确认夹爪为空并且整条返回路径无遮挡，再执行：

```bash
python so101_home.py home \
  --port /dev/ttyACM0 \
  --pose "$HOME/lerobot/poses/pick_place_02_start.json" \
  --execute
```

程序倒计时 3 秒后开始归位。新轨迹的结束姿态可能变化，所以旧轨迹的归位成功不能替代这次返回路径验证。确认反馈稳定到位、没有碰撞或明显受阻后，再继续。

## 6. 空载验证完整回放和自动归位

继续不放物块，执行：

```bash
python so101_home.py demo \
  --port /dev/ttyACM0 \
  --pose "$HOME/lerobot/poses/pick_place_02_start.json" \
  --execute
```

它自动执行：**归位到新起点 → 回放第 2 条轨迹 → 正常结束后缓慢返回新起点 → 保持上力**。

L 主臂不需要操作。动作由 F 自行完成。回放保持原数据帧率，目标变化限幅与录制统一为已实测可完成的 `5`。任何中断或回放失败都不会继续自动返回。

2026-10-15 更新：用户反馈回放限幅 `2` 时明显滞后/幅度不足，改为 `5` 后可以正常完成。请使用更新后的 `so101_home.py`；如果 Ubuntu 仍是旧副本，需要把回放命令中的 `--robot.max_relative_target=2` 改为 `--robot.max_relative_target=5`。只改回放参数，保留归位用的 `LEAD=2` 和缓慢归位速度。

**第 2 条轨迹的命令必须带上上述 `--pose` 路径。** 不填会使用旧的默认起点，第 1 条和第 2 条不会自动切换。

## 7. 放入物块，再运行一次相同命令

确认整套空载动作顺利后，把物块放回录制时的 A 区位置和朝向，清空 B，手退出运动区域。再次执行第 6 步同一条 `demo` 命令。

观察物块是否抓住、放稳，夹爪是否为空，再观察自动归位。出现物块没放下、掉落后卡住、顶住或异响，应停止。需要下一次演示时，在程序结束后重新摆物块，再手动运行同一命令；程序不会无限循环。

## 8. 结束使用

归位、回放和录制结束后都可能仍保持上力。先扶稳前臂，再执行：

```bash
python so101_home.py release \
  --port /dev/ttyACM0 \
  --pose "$HOME/lerobot/poses/pick_place_02_start.json" \
  --execute
```

确认卸力后断开 F 电机电源，正常关闭虚拟机。不要无人照看地长时间保持上力。

出现异常运动，应立即切断 F 电机电源；`Ctrl+C` 不是硬件急停。归位采用关节插值，不具备自动避障；无相机回放也不会修正物块移动、底座偏移或夹爪滑移。
