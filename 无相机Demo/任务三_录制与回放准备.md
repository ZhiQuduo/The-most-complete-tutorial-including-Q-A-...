# 任务三：无相机遥操作录制与单次回放

整理日期：2026-11-02。以下命令在 Ubuntu 的同一个 Bash 终端分段执行。
本页依据 Windows 项目维护源整理，未实时连接 Ubuntu，未执行录制或运动。

这是固定轨迹回放，不是视觉策略。物体位置、底座、工具和起始条件改变后，回放不会自动修正。
本次先不增加相机，避免把轨迹录制与双相机数据验收混在一起。

## 0. 动作前条件

- 先正常退出语音助手、旧遥操作、回放、预览和模型控制进程，不同时占用设备。
- 10 月 30 日的肘部跟随保护及肩部超时尚不能视为已解决。若当前普通小幅遥操作仍不正常，停止录制，不用回放诊断故障。
- 固定两臂底座，核对适配器与电源，夹爪空载，线缆有余量，路径无人且无遮挡。
- 两臂先处于相近姿态。上力的 Follower 不能强行手扳；卸力前必须支撑手臂。
- 不覆盖校准，不重新设置电机 ID，不提高力矩/PID，不删除已有数据。意外弹出校准流程时先停止核对。
- 正常停止使用 Ctrl+C；异常动作时应切断 Follower 电机电源，软件退出不是硬件急停。

## 1. 环境、设备与独立路径（不运动）

```bash
source "$HOME/miniforge3/etc/profile.d/conda.sh"
conda activate so101
cd "$HOME/lerobot"
python -m pip check
python -m serial.tools.list_ports -v
pgrep -af 'lerobot|teleop|record|preview|voice_tasks|pipeline|handshake' || true
```

历史现场拔插确认 Follower 控制板 serial 为 `5B79080161`，Leader 为 `5B90101857`。
不要沿用 ACM 编号；如果硬件更换、角色不清楚，先做现场拔插确认。
下面按已知控制板序列号查询当前端口；找不到或重复时拒绝继续。

```bash
find_arm_port() {
  python - "$1" <<'PY'
import sys
from serial.tools.list_ports import comports
ports = [p.device for p in comports() if p.serial_number == sys.argv[1]]
if len(ports) != 1:
    raise SystemExit(f"Expected one board for {sys.argv[1]}, got {ports}")
print(ports[0])
PY
}
F_PORT=$(find_arm_port 5B79080161)
L_PORT=$(find_arm_port 5B90101857)
printf 'Follower=%s\nLeader=%s\n' "$F_PORT" "$L_PORT"
test -n "$F_PORT" && test -n "$L_PORT" && test "$F_PORT" != "$L_PORT"
test -r "$F_PORT" && test -w "$F_PORT" && test -r "$L_PORT" && test -w "$L_PORT"
python so101_home.py --help
```

任一步失败就停在这里。不要用 chmod 666 代替权限排查。

每次新录制只生成一次名称；同一条轨迹后续不要重新运行以下赋值：

```bash
DEMO_NAME="so101_task3_$(date +%Y%m%d_%H%M%S)"
DEMO_REPO="local/$DEMO_NAME"
DEMO_ROOT="$HOME/lerobot/recordings/$DEMO_NAME"
DEMO_POSE="$HOME/lerobot/poses/${DEMO_NAME}_start.json"
printf 'DEMO_NAME=%s\nDEMO_REPO=%s\nDEMO_ROOT=%s\nDEMO_POSE=%s\n' \

test ! -e "$DEMO_ROOT" && test ! -e "$DEMO_POSE"
```

名称含时间戳，不使用或覆盖任务一、二的数据目录。

## 2. 小幅普通遥操作确认（会运动，不保存数据）

只有动作前条件满足时运行。启动后先缓慢移动 Leader 很小幅度；有跟随异常就停止。

```bash
lerobot-teleoperate \
  --robot.type=so101_follower --robot.port="$F_PORT" --robot.id=follower_arm \
  --robot.use_degrees=true --robot.max_relative_target=5 \
  --robot.disable_torque_on_disconnect=false \
  --teleop.type=so101_leader --teleop.port="$L_PORT" --teleop.id=leader_arm \
  --teleop.use_degrees=true --fps=30 --display_data=false
```

选好任务起点，两臂停稳后 Ctrl+C 正常退出。Follower 退出后仍保持力矩，不要手扳。
这里的 `max_relative_target=5` 沿用项目现有录制/回放参数，是单次更新的位置差限制，不是 5 度/秒或总行程限制，也不保证故障消失。

## 3. 录制一个 episode（会运动并保存数据）

```bash
lerobot-record \
  --robot.type=so101_follower --robot.port="$F_PORT" --robot.id=follower_arm \
  --robot.use_degrees=true --robot.max_relative_target=5 \
  --robot.disable_torque_on_disconnect=false \
  --teleop.type=so101_leader --teleop.port="$L_PORT" --teleop.id=leader_arm \
  --teleop.use_degrees=true \
  --dataset.repo_id="$DEMO_REPO" --dataset.root="$DEMO_ROOT" \
  --dataset.single_task="Perform task three" \
  --dataset.fps=30 --dataset.num_episodes=1 \
  --dataset.episode_time_s=60 --dataset.reset_time_s=0 \
  --dataset.video=false --dataset.push_to_hub=false --dataset.no_stamp=true \
  --display_data=false --play_sounds=false
```

看到 `Recording episode 0` 后先停稳 3-5 秒，再手动完成一次任务三，最后停在安全位置，等 60 秒结束并完成写盘。
本命令本身就是遥操作加录制，不要同时再运行普通遥操作命令。
若命令失败、目录已存在或帧数异常，停下保留现场信息；不要删除轨迹、添加 resume 或直接回放。
60 秒含起止等待，后续回放也包含这些等待，不自动裁剪。

## 4. 核对数据并保存专属起点（不运动）

```bash
python - "$DEMO_ROOT" <<'PY'
import json, sys
from pathlib import Path
import pyarrow.parquet as pq
root = Path(sys.argv[1])
info = json.loads((root / "meta/info.json").read_text())
files = sorted((root / "data").rglob("*.parquet"))
assert files, "No Parquet data"
rows = sum(pq.ParquetFile(p).metadata.num_rows for p in files)
assert rows > 0, "Empty recording"
assert info["total_episodes"] == 1, "Expected one episode"
assert info["total_frames"] == rows, "Metadata/Parquet frame count mismatch"
print("ROOT:", root)
print("EPISODES:", info["total_episodes"], "FRAMES:", rows, "FPS:", info["fps"])
print("This is a file check, not motion acceptance.")
PY
```

文件检查通过后，分两步运行：

```bash
python so101_home.py save-start \
  --port "$F_PORT" --dataset "$DEMO_ROOT" --repo-id "$DEMO_REPO" \
  --pose "$DEMO_POSE"
```

```bash
python so101_home.py check --port "$F_PORT" --pose "$DEMO_POSE"
```

`save-start` 从新录制的 episode 0 第 0 帧提取实际反馈，并绑定数据、校准和 USB serial。
它不表示当前已在起点；`check` 才比较当前反馈和起点。校准或角色不匹配时停止，不改保护。

## 5. 第一次空载归位（会运动）

先移走物体，确认夹爪空载和整条返回路径安全。以下是关节插值，不会自动避障。

```bash
python so101_home.py home --port "$F_PORT" --pose "$DEMO_POSE" --execute
```

如果跨度保护、跟随保护或超时触发，不进行回放；不提高阈值或重复试动。

## 6. 定义并执行一次回放

以下仅定义函数，不立即运动。显式采用现有单次更新限幅 5，避免依赖旧 helper 内的回放默认值。

```bash
replay_task3_once() {
  python so101_home.py home --port "$F_PORT" --pose "$DEMO_POSE" --execute || return
  lerobot-replay \
    --robot.type=so101_follower --robot.port="$F_PORT" --robot.id=follower_arm \
    --robot.use_degrees=true --robot.max_relative_target=5 \
    --robot.disable_torque_on_disconnect=false \
    --dataset.repo_id="$DEMO_REPO" --dataset.root="$DEMO_ROOT" \
    --dataset.episode=0 --play_sounds=false || return
  python so101_home.py home --port "$F_PORT" --pose "$DEMO_POSE" --execute || return
}
```

确认第 5 步归位成功，先空载执行一次：

```bash
replay_task3_once
```

流程为归位 -> 官方 episode 0 回放 -> 正常完成后归位。任一步失败则不继续，不循环、不排队。
空载通过后，恢复录制时物体位置、方向和场景，手退出运动区，再人工执行一次同一命令验证任务。
回放读的是录制动作请求，不是保证精确复现反馈位置；尤其要检查有无请求/实际失跟。

## 7. 结束使用与语音接入

录制、归位和回放后 Follower 可能仍保持力矩。先托稳前臂，再卸力：

```bash
python so101_home.py release --port "$F_PORT" --pose "$DEMO_POSE" --execute
```

如果尚未生成起点文件，不要使用不存在的文件卸力；先支撑从臂再切断对应电机电源。

录完后保留这段输出，供后续绑定任务三：
