# 遥操作、轨迹回放与语音系统操作手册

本章的三个阶段是项目最重要的可复用基础：先用遥操作确认机械链路，再记录可重复轨迹，最后用语音只做“已验证任务的调度”。语音层不负责路径规划，也不会让错误场景自动变安全。

## 1. 每次启动 Ubuntu

把 Leader、Follower 控制板和需要的相机从 Windows 主机分配给 VMware。不要根据 `ACM0/ACM1` 猜角色；重新插拔后先枚举或使用 `/dev/serial/by-id` 稳定链接。

```bash
source "$HOME/miniforge3/etc/profile.d/conda.sh"
conda activate so101
cd "$HOME/lerobot"
python -m pip check
python -m serial.tools.list_ports -v
```

若出现 `Permission denied`，长期做法是把用户加入 `dialout` 后重新登录：

```bash
sudo usermod -aG dialout "$USER"
```

不要把 `chmod 777`、重新设置电机 ID 或重新校准当成每次开机步骤。

## 2. 遥操作

运行类型：**真实遥操作，会驱动 Follower，不是 ACT 推理。**

```bash
F_PORT=/dev/ttyACM0   # 示例：换成当前确认的 Follower
L_PORT=/dev/ttyACM1   # 示例：换成当前确认的 Leader

printf 'Follower=%s\nLeader=%s\n' "$F_PORT" "$L_PORT"

lerobot-teleoperate \
  --robot.type=so101_follower \
  --robot.port="$F_PORT" \
  --robot.id=follower_arm \
  --robot.max_relative_target=5 \
  --robot.disable_torque_on_disconnect=false \
  --teleop.type=so101_leader \
  --teleop.port="$L_PORT" \
  --teleop.id=leader_arm \
  --fps=30 \
  --display_data=false
```

提示复用校准时，只有名称、用户和校准目录都正确才按 Enter。让两臂从相近的稳定姿态开始，先做空载小幅动作。结束前支撑 Follower，再按 `Ctrl+C`；程序可能按项目策略继续保持力矩。

## 3. 轨迹录制

运行类型：**Leader 遥操作 + Follower 运动 + 本地数据记录，不是模型训练或推理。**

先生成唯一数据名：

```bash
DEMO_NAME="so101_pick_place_$(date +%Y%m%d_%H%M%S)"
DEMO_REPO="local/$DEMO_NAME"
DEMO_ROOT="$HOME/lerobot/recordings/$DEMO_NAME"
DEMO_POSE="$HOME/lerobot/poses/${DEMO_NAME}_start.json"
```

录制一条：

```bash
lerobot-record \
  --robot.type=so101_follower \
  --robot.port="$F_PORT" \
  --robot.id=follower_arm \
  --robot.max_relative_target=5 \
  --robot.disable_torque_on_disconnect=false \
  --teleop.type=so101_leader \
  --teleop.port="$L_PORT" \
  --teleop.id=leader_arm \
  --dataset.repo_id="$DEMO_REPO" \
  --dataset.root="$DEMO_ROOT" \
  --dataset.single_task="Move the block from A to B" \
  --dataset.fps=30 \
  --dataset.num_episodes=1 \
  --dataset.episode_time_s=60 \
  --dataset.reset_time_s=0 \
  --dataset.video=false \
  --dataset.push_to_hub=false \
  --dataset.no_stamp=true \
  --display_data=false \
  --play_sounds=false
```

动作应包含稳定起始、接近、夹取、抬起、搬运、放下、释放和撤离。录制完成后用现有 helper 保存第 0 帧实际反馈为起点：

```bash
python so101_home.py save-start \
  --port "$F_PORT" \
  --dataset "$DEMO_ROOT" \
  --repo-id "$DEMO_REPO" \
  --pose "$DEMO_POSE"

python so101_home.py check --port "$F_PORT" --pose "$DEMO_POSE"
```

这两步是文件/反馈检查，不等于执行归位。

## 4. 轨迹回放

运行类型：**确定性轨迹回放，会驱动 Follower；没有视觉闭环。** 物体、底座和起姿发生偏移时，它不会自行修正。

```bash
replay_once() {
  python so101_home.py home \
    --port "$F_PORT" --pose "$DEMO_POSE" --execute || return

  HF_HUB_OFFLINE=1 lerobot-replay \
    --robot.type=so101_follower \
    --robot.port="$F_PORT" \
    --robot.id=follower_arm \
    --robot.max_relative_target=5 \
    --robot.disable_torque_on_disconnect=false \
    --dataset.repo_id="$DEMO_REPO" \
    --dataset.root="$DEMO_ROOT" \
    --dataset.episode=0 \
    --play_sounds=false || return

  python so101_home.py home \
    --port "$F_PORT" --pose "$DEMO_POSE" --execute
}
```

先拿走物体做空载 `replay_once`，确认整条路径无碰撞，再恢复与录制一致的场景做带物体回放。函数在任一步失败后停止，不会继续落入下一阶段。完整流程见[统一限幅 5 的原始操作文档](../../无相机Demo/遥操作到回放完整代码_统一限幅5.md)。

## 5. 中文语音系统

语音系统使用两个隔离环境：

- `so101_voice`：Vosk、麦克风和口令识别。
- `so101`：真正的归位和回放 helper。

安装识别环境：

```bash
conda create -n so101_voice python=3.10 -y
conda activate so101_voice
python -m pip install vosk
mkdir -p "$HOME/so101_voice/models"
cd "$HOME/so101_voice/models"
wget -c https://alphacephei.com/vosk/models/vosk-model-small-cn-0.22.zip
python -m zipfile -e vosk-model-small-cn-0.22.zip .
```

当前维护源为[voice_tasks.py](../../语音任务助手/voice_tasks.py)，Ubuntu 部署入口为[start_voice_tasks_v3.sh](../../语音任务助手/start_voice_tasks_v3.sh)。发布到自己的设备前，应把设备 by-id、数据集和 pose 改成配置变量。

已支持的精确口令：

- “执行任务一”/“完成任务一”。
- “执行任务二”/“完成任务二”。
- “请完成任务三”/“完成任务三”/“执行任务三”。
- “查询状态”。
- “停止任务”。

先做不访问麦克风、串口或电机的配置检查：

```bash
bash "$HOME/so101_voice/start_voice_tasks_v3.sh" --check-config
```

再做只监听、不运动的模拟：

```bash
bash "$HOME/so101_voice/start_voice_tasks_v3.sh"
```

只有手动执行同一轨迹已经通过、现场已恢复且模拟绑定正确，才进入真实模式：

```bash
bash "$HOME/so101_voice/start_voice_tasks_v3.sh" --execute
```

真实模式的任务流程是 `归位 → episode 0 回放 → 归位`，不是 ACT。运行中不排队；中断或失败后锁定，必须检查现场并重启。语音停止通过 SIGINT 请求软件停止，不能代替断开 Follower 电机电源。

## 6. 语音阶段解决的关键问题

旧启动器直接把 `/dev/serial/by-id/...` 传给执行器，但执行器用 `serial.tools.list_ports` 返回的规范节点比较，导致明明链接存在却拒绝设备。修复方式是在启动器中：

```bash
FOLLOWER_LINK=/dev/serial/by-id/usb-...-if00
F_PORT=$(readlink -e -- "$FOLLOWER_LINK") || exit 1
```

然后把解析后的 `/dev/ttyACM*` 传给 helper，同时仍由 helper 校验 USB 序列身份。修复后必须退出旧语音进程再启动，因为运行中的 shell 不会自动加载新代码。
