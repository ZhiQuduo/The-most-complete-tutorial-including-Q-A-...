# 验证边界、安全说明与 GitHub 发布清单

## 1. 如何描述结果

本项目采用四级证据，公开 README、论文或比赛材料都应沿用：

1. **文件存在**：代码、配置或文档已经写出。
2. **软件验证**：语法、单元测试、数据审计、离线推理或网络协议通过。
3. **实机链路验证**：机械臂按预期运动、保护和遥测正常。
4. **物理任务成功**：黄色方块最终稳定放在蓝色方块上，并通过人工/视频确认。

不能用 1/2 代替 3，也不能用“运行 300 秒未崩溃”代替 4。当前可公开的准确表述是：

- 双相机 50 条数据审计通过，ACT 训练正常结束。
- 跨机双相机推理协议、CUDA 推理和 Ubuntu 有界执行已跑通。
- 多个保护停止都可由 telemetry 复现和解释。
- 用户观察到一次抓起黄色方块；当次在夹爪接触滞后保护处停止。
- 尚无足够的重复实机试验统计，不声明稳定叠放成功率。

## 2. 实机安全边界

- Windows 推理服务必须保持 `motion_enabled=false`，不得连接机器人串口。
- Ubuntu 是唯一运动控制端；相机和串口不能同时被多个进程占用。
- P=32 只用于 ID3 `elbow_flex`；每次连接后读取验证。不得把这一设置扩展到其他轴。
- 不因模型停止而提高力矩限制；I/D、Lock 和其他参数保持已验证值。
- 5°是本项目任务阶段的有界投影/反馈容差，不是无条件允许关节瞬移 5°。
- 自动归位是关节空间插值，不会避障。需要 15°以上粗接管时先用遥操作移近，不直接放宽归位入口。
- `Ctrl+C`、方向键和语音停止是软件控制，不是硬件急停。异常运动应立即切断 Follower 电机电源。
- 程序退出后可能继续上力；支撑机械臂后再释放或断电，不强扳上力关节。

## 3. 不应上传到公共 GitHub 的内容

`.gitignore` 已排除常见大文件和隐私文件，但忽略规则不会删除已经被 Git 跟踪的内容。发布前必须确认：

- `datasets/`、`recordings/`、视频、Parquet。
- `outputs/`、checkpoint、`*.safetensors`。
- 训练和 rollout 日志、telemetry、相机快照。
- `.venv/`、Conda 环境、Hugging Face cache。
- 真实校准 JSON、起始姿态（如果不希望公开设备几何范围）。
- SSH 私钥、令牌、`.env` 和 Windows 用户目录。
- Ubuntu 安装 ISO/压缩包。

如果大文件已经进入历史，仅增加 `.gitignore` 不够；发布前要在本地未推送分支清理索引，或使用 `git filter-repo` 清理历史。

## 4. 公开前必须参数化的本机信息

当前代码仍含本机部署值，所以**还不应直接公开推送**：

- Leader/Follower USB serial 与 `/dev/serial/by-id`。
- 相机 `/dev/v4l/by-id`、`/dev/v4l/by-path`。
- Windows/VM 的私有局域网 IP。
- 用户名和 `/home/<user>/...`。
- Windows 本机仓库绝对路径。
- 固定 checkpoint 路径和 SHA-256。
- 本机数据集名称、pose 路径与语音任务绑定。

建议增加一个不含真实值的 `.env.example`：

```dotenv
SO101_FOLLOWER_BY_ID=/dev/serial/by-id/REPLACE_ME
SO101_LEADER_BY_ID=/dev/serial/by-id/REPLACE_ME
SO101_FRONT_CAMERA=/dev/v4l/by-id/REPLACE_ME
SO101_WRIST_CAMERA=/dev/v4l/by-id/REPLACE_ME
SO101_GPU_SERVER=http://WINDOWS_HOST:8092
SO101_VM_HOST=VM_ADDRESS
SO101_VM_USER=ubuntu_user
SO101_CHECKPOINT=/path/to/pretrained_model
```

代码默认值应是占位符或通过命令行显式提供；缺少关键配置时 fail closed，不能猜设备。

### 扫描本机标识与密钥关键词

仓库已提供一个只读扫描器：

```powershell

```

## 7. GitHub 初始化建议

本轮没有替用户创建远程仓库或执行 push。完成脱敏后可在根目录：

```powershell
git init
Get-Content .\PUBLIC_RELEASE_FILES.txt |
  Where-Object { $_ -and -not $_.StartsWith('#') } |
  ForEach-Object { git add -- $_ }
git status
git commit -m 'Document SO-101 dual-camera ACT project'
```

在 `git add` 之后、`commit` 之前必须重新看 `git status` 和 `git diff --cached --stat`。许可证由作者选择；未明确选择前不要随意声称 MIT/Apache/GPL。

## 8. 后续实验建议

1. 固定五个黄色方块起点，每个起点至少重复 10 次，记录成功、漏夹、碰撞、保护停止和超时。
2. 保存两路视频与 telemetry 的共同 run ID，使物理结果能追溯到模型、checkpoint 和保护参数。
3. 把“抓起成功”“放到蓝块上”“稳定撤离”分成三个评价指标。
4. 统计边界投影比例；若 shoulder_lift 长期大量投影，回到数据标签/校准处理，而不是继续放宽。
5. 增加不访问硬件的 CI：Python 语法、单元测试、Shell 语法、PowerShell 参数检查和 Markdown 链接检查。
