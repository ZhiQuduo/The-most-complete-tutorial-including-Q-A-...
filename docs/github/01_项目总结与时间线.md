# 项目总结与时间线

## 1. 项目目标

项目最初目标是把 SO-101 Pro 散件系统搭建到可用状态，逐步掌握主从臂遥操作、示范轨迹记录和自动回放。随后加入中文语音触发，并把工作推进到基于双相机的 ACT 模仿学习：让机械臂根据固定全局视角与腕部视角，把黄色方块放到蓝色方块上。

项目不是一次性“跑一个 Demo”，而是建立了以下完整链路：

```text
散件与供电 → 电机 ID → 机械装配 → 校准 → 遥操作
→ 轨迹录制/归位/回放 → 语音任务路由
→ 双相机采集/清洗 → ACT 训练 → Windows GPU + Ubuntu 实机跨机推理
```

## 2. 硬件与软件组成

### 硬件

- SO-101 Pro Leader 主臂与 Follower 从臂。
- 每条独立总线各有 6 个电机，关节顺序为：
  `shoulder_pan=1`、`shoulder_lift=2`、`elbow_flex=3`、`wrist_flex=4`、`wrist_roll=5`、`gripper=6`。
- 固定全局相机 `front`：观察机械臂、黄色方块和蓝色方块的整体关系。
- 腕部相机 `wrist`：补充夹爪附近的局部视觉信息。
- Windows 笔记本 GPU：NVIDIA GeForce RTX 5060 Laptop GPU。
- Ubuntu 22.04 VMware 虚拟机：连接 USB 控制板和相机，负责实机控制。

Leader 和 Follower 在不同串行总线上，因此两边各自使用 ID 1–6 是正常的。`/dev/ttyACM0` 不是电机 ID，`--robot.id=follower_arm` 也不是电机 ID；后者是 LeRobot 校准文件使用的设备名称。

### 从散件到可校准机械臂的装配顺序

项目实际采用的工程顺序可以概括为：

1. 先按 Leader/Follower 分开控制板、电机、线缆与电源，不混用两套总线。
2. 在单电机连接条件下依次写入 1–6 号 ID；成功后立即贴 `L1–L6`、`F1–F6` 标签。
3. 按 `底座旋转 → 肩抬升 → 肘 → 腕俯仰 → 腕旋转 → 夹爪` 的运动链组装；每装一段先手动确认活动方向和线缆余量。
4. 固定底座，保证腕部/夹爪到全工作空间时线缆不拉紧、不缠绕、不进入齿轮或关节间隙。
5. 接入与各自控制板匹配的电源和 USB，只在确认角色后运行 LeRobot 配置/校准。
6. Leader 和 Follower 分别保存 `leader_arm`、`follower_arm` 校准；日常启动复用，不重复 setup motors。
7. 第一次遥操作让两臂从相近中间姿态开始，只做单轴、小幅、空载试动，再逐步进入搬运。

早期历史记录能证明环境建立、电机设置流程和后续遥操作可用，但没有保存一套逐螺钉、逐扭矩的装配验收表。因此这里不虚构螺钉规格或官方扭矩值；公开版若要写成通用装配教程，应补充套件 BOM、每个关节的装配照片和厂家手册引用。

### 软件

- Ubuntu 22.04.5 LTS、Conda 环境 `so101`、LeRobot。
- Windows Python/CUDA 环境用于训练和推理。
- Vosk 中文离线识别，独立 Conda 环境 `so101_voice`。
- HTTP/JSON 双相机推理协议：Ubuntu 上传两张 PNG 和六维状态，Windows 返回 `30×6` ACT 动作块。

## 4. 从单相机到双相机的关键转折

早期单相机 ACT 已经证明模型能在 Windows GPU 上推理、Ubuntu 能安全接收动作，但 45 秒运行没有稳定完成叠放。进一步对比训练图像和现场图像后发现：固定相机大体相似，而腕部附近的初始环境和夹爪局部信息是单相机难以覆盖的变量。

因此没有给旧 checkpoint 强行增加第二个图像键，而是重新采集同步双相机数据并训练独立模型。这是结构性修改：训练时和部署时都必须同时使用精确键名 `observation.images.front` 与 `observation.images.wrist`。

## 5. 数据与模型结果

正式数据集：

- 任务：`Place the yellow cube on top of the blue cube`。
- 50 episodes，20,478 frames，30 FPS。
- 两路视频均解码为 20,478 帧。
- 训练/验证按 episode 划分为 40/10；训练子集为 16,554 帧。
- 训练前通过联系表抽帧检查，并对已知问题 episode 剔除/补录。

ACT：

- 15,551,494 个可学习参数。
- `dim_model=256`，`dim_feedforward=1024`。
- encoder 2 层，decoder 1 层，VAE encoder 2 层。
- `chunk_size=30`，`n_action_steps=10`。
- batch size 4，32,764 steps，约 8 epochs。
- 正式训练约 1 小时 55 分钟后正常结束并保存最终 checkpoint。

## 6. 当前结论

项目已经完成从硬件、示范、语音到学习策略与跨机部署的完整工程闭环。最重要的工程收获不是“把保护阈值调大”，而是把每个环节拆开验证：设备身份、校准、相机画面、数据质量、训练、网络、动作格式、机械边界和物理结果各自有独立证据。

尚未完成的研究结论是“模型在不同起点上具有稳定叠放成功率”。公开仓库应继续保留这个边界，后续用固定测试集和多次实机试验报告成功率、失败类型和平均耗时。
