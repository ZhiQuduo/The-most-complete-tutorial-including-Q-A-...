### 2026-10-29 宿主机文件只读核查

- 实际 VM 配置：`D:\具身智能\虚拟机\Ubuntu 22.04.vmx`，不是早期建议的 `虚拟机\Ubuntu22-SO101\` 子目录。
- `displayName="Ubuntu 22.04"`，`guestOS="ubuntu-64"`，`memsize="8192"`，`numvcpus="2"`，`cpuid.coresPerSocket="1"`；即配置了 8 GiB 内存、2 个虚拟 CPU，与早期建议的 4 核不能混记。
- `ethernet0.connectionType="nat"`，`usb.present="TRUE"`，`usb_xhci.present="TRUE"`；这些配置不等于当前实际 USB 已透传。
- 虚拟盘描述符 `Ubuntu 22.04.vmdk` 为 `twoGbMaxExtentSparse`，共 13 个 extent；总计 104857600 个 512-byte 扇区，即 **50 GiB**，不是早期建议的 80GB。未修改容量或挂载 VMDK。
- ISO 实际存在于 `D:\具身智能\Ubuntu22.04 安装包\ubuntu-22.04.5-desktop-amd64.iso`，大小 4762707968 bytes；这与最初建议的 `安装包\` 路径不同。VMX 中文路径以文件编码读取为准，默认解码显示乱码不应直接认定路径损坏。
- 此处是宿主机静态配置观察，不代替 Ubuntu 运行态、剩余磁盘空间或设备通信验证。

## 7. 给接手 Agent 的恢复顺序与只读检查

1. 先读 `docs/README.md`，寻找后续聊天的日期化交接；本文件是初始安装基线。
2. 当前授权为文档维护，不是让本轮自行启动硬件。将来继续设备任务时，先在正确 guest 终端验证现状，不重装已经通过的环境。
3. 只读入口（本轮没有在 guest 执行）：

```bash
conda activate so101
cd ~/lerobot
python -c 'import sys; print(sys.executable); print(sys.version)'
python -m pip check
python -m pip show lerobot torch torchvision torchcodec
git remote -v
git rev-parse HEAD
git status --short
ffmpeg -version
df -h "$HOME"
python -m serial.tools.list_ports -v
ls -l /dev/serial/by-id/ 2>/dev/null
id -nG
```

`/dev/serial/by-id/` 没有条目不等于控制板不存在，仍以实际枚举和设备属性交叉判断。如果 Conda 未加载，先查已有安装而非重装；本聊天使用的是 **Miniforge**，旧根 README 中只列 miniconda/anaconda 的恢复分支并不覆盖本聊天默认安装路线。

4. 找到两臂真实校准及后续成功命令，再决定是否需要重新设置电机或校准。本聊天早期示例名称不是最终配置。
5. 对用户保持一次一个小动作、等待输出的指导节奏。USB 无响应先检查透传和数据线，不把它归咎为必须重装 LeRobot。
6. USB 枚举时先只连控制板 USB，不接电机电源；无法枚举则查具体板卡供电设计，不以盲目接适配器作为排错方法。后续动作前再完成实物电源核对和工作区检查。
